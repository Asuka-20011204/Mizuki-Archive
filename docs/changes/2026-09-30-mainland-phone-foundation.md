# 大陆手机号认证基础

- 日期：2026-09-30
- 目的：明确中国大陆手机号范围，完成独立身份和安全验证码基础，不伪造短信投递。

## 范围与取舍

- 号码统一为 `+86` 加 11 位 ASCII 数字；独立 `users.phone` 唯一索引和 `phone_challenges`，不自动合并邮箱账号。
- 服务端新增可注入的短信发送端口、注册/登录和一次性消费流程；HTTP 增加条件路由与能力探测、IP/号码限流，前端标签只在服务端显式启用时出现。
- 未选择供应商时 `cmd/server` 不装配 `PhoneAuth`，公开手机路由为 404，登录页不显示手机入口。没有真实投递，也没有真实浏览器手机号验收。

## 验证

- 先写手机号规范化、注册登录、重放和发送失败用例，观察到未实现时编译失败后再实现：通过。
- `go test ./...`、`go vet ./...`、`npm --prefix web run build`、`npm --prefix web test` 和 `git diff --check`：通过。HTTP 测试发送器验证条件路由、注册、登录、重放拒绝、服务端用户归属；默认配置验证手机路由不暴露。
- 新建独立 MySQL 8.4 容器，仅针对隔离 `mizuki_test_phone` 运行真实迁移首次/重复执行、模拟迁移登记中断重试、手机号唯一约束及并发一次性消费：通过；临时容器已停止，未触碰开发库。首次测试 DSN 拼接有误，修正后暴露并修复了迁移元数据扫描问题，再次验证通过。

## 风险与下一步

- 当前手机入口不可用；还需确定短信供应商、签名模板、预算上限及适用隐私要求，实施真实发送适配、供应商故障处理和浏览器端到端测试。不能用测试发送器启用生产接口。
- 号码格式校验不等于实名或号段有效性验证；后续账号绑定不能通过手机号推断旧邮箱用户所有权。
- 接入供应商前须实现全局发送预算和过期挑战清理，并确保多实例部署存在可靠共享限流；当前限流键用服务端 HMAC 派生，不把低熵手机号普通哈希暴露到 Redis 键名。
- 当前本地 `.env` 在执行 `docker compose ps` 时出现解析错误（第 74 行为非注释中文文本）；本轮未改动该私有文件，使用隔离容器验证，不宣称 Compose 当前可正常启动。
