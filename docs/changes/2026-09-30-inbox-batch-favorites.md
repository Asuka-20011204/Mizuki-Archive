# 文件与外部卡片批量收藏

- 日期：2026-09-30
- 目的：在统一的用户资料空间中，为文件和外部卡片增加可重试、可解释的收藏目标操作。

## 范围与取舍

- 新增 `015` 迁移，为历史外部卡片默认设置未收藏，DDL 在版本锁内可重试；不修改原有链接状态。普通卡片编辑不写收藏列。
- `PATCH /api/batch/favorites` 接受 1–50 个不同来源/ID 及明确布尔目标；事务先校验全部用户归属和文件软删除状态，再写入文件与卡片收藏，返回真正变化的项目。重复目标返回零变化。
- 收件箱显示两类资料收藏状态及当前页批量目标，提交前确认数量；卡片列表也提供单项收藏按钮。反向操作有并发覆盖提示，未实现跨会话版本化回滚；没有把本切片冒充归档或删除。

## 验证

- 服务层/HTTP 自动测试覆盖身份、非法与重复条目、缺少布尔目标、匿名、跨账号混合批次、尾随 JSON、限流和实际变化项。
- 独立 MySQL 8.4 `mizuki_test_` 临时库：验证 `015` 首次/重复/DDL 已执行但版本记录丢失的迁移、两表收藏与取消幂等、越权及软删除整批拒绝、卡片普通编辑不清除收藏。临时容器结束后停止，不接触开发库。
- `go test ./...`、`go vet ./...`、`npm --prefix web test`（现有 11 项不覆盖收藏组件）、`npm --prefix web run build` 与差异检查已通过；隔离 MySQL 全量仓储回归首轮因旧用例仍硬编码 12 条迁移记录失败，改为 15 后在新的隔离库通过。浏览器内勾选、确认和反向操作仍待人工验收。

## 风险与下一步

- 客户端响应丢失后重试可能返回空变化项，因此一次反向恢复不能保证恢复首次变化；并发其他会话修改后同样可能覆盖新状态。若要可靠撤销，需要持久操作标识与版本冲突检测。
- 仍需为已整理文件提供批量入口，并单独设计归档及删除的恢复、原件清理、审计语义。大陆手机号基础仍仅规范化为 `+86`，未选定真实短信服务商之前不开放手机注册/登录。
