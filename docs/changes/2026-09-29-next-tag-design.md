# 2026-09-29 · 下一阶段手动标签设计

## 目的

在收藏之后确定 V1 下一条垂直切片，补足个人数字资料的“整理和找回”能力，同时保持 Go MVC/GORM 单体边界，不为了练习 Redis/MQ 提前增加基础设施。

## 本轮结论

- 下一功能：手动标签、标签编辑和单标签筛选。
- 采用 `tags` + `resource_tags` 规范化关系表；资料原文件和收藏字段不改变。
- 使用 `PUT /api/resources/:id/tags` 整体替换，显式数组保证幂等；列表查询增加精确 `tag` 参数。
- 实现前必须先补版本化迁移执行器和 `002_manual_tags.sql`，不能继续只依赖 `CREATE TABLE IF NOT EXISTS` 的初始迁移。
- 事务只覆盖 MySQL 元数据；失败必须保留旧关联，前端保留未保存草稿。

## 相关设计

- 长期架构决定见 [ADR 0003](../decisions/0003-manual-tags.md)。
- 当前产品已把标签列入 V1 目标，但尚未实现；本记录不把提案写成已完成能力。

## 下一轮实现顺序

1. 先补迁移版本表、迁移测试和标签规范化的 Service 单测。
2. 增加 Repository 事务接口及 MySQL 集成测试。
3. 接入 Controller/API，补认证、Origin、输入上限、回滚和分页测试。
4. 接入 Vue 详情编辑、建议列表、标签筛选和错误恢复。
5. 做 Go/前端检查与真实浏览器验收，再决定是否进入名称编辑或删除设计。

## 当前未实现与风险

- 设计尚未改变数据库、接口或前端行为。
- 标签唯一键竞争、孤儿标签清理和 Unicode 规范化需要实现时用真实 MySQL 验证；不能只依赖内存替身。
- 单管理员并发替换采用最后提交者获胜，不提供冲突提示；如果后续出现多人或多客户端编辑需求，需要新 ADR。
