# 2026-09-29 · V1 资料管理闭环

## 目的与范围

完成个人数字信息管理系统 V1 的资料整理与查看闭环，并把代码、迁移、测试、前端交互和运行文档同步到同一状态。本轮不引入 Redis、RabbitMQ、Worker 或多人协作能力。

## 完成内容

- 增加手动标签：建议、规范化、去重、整体替换、清空和单标签筛选。
- 增加展示名称编辑：只修改用户可见名称，不改变原始上传名和受控存储键。
- 增加安全预览：图片内联预览；TXT/Markdown 限制为 1 MiB 的纯文本预览；PDF 明确走下载。
- 增加软删除：先隐藏数据库记录并解除标签，再清理原件；文件清理失败时资料仍保持隐藏。
- 增加迁移版本跟踪：`001_init`、`002_manual_tags`、`003_soft_delete`，重复迁移可安全执行。
- 更新 Vue 交互：标签筛选/编辑、名称编辑、预览、删除确认、焦点恢复、空状态和错误恢复。
- 补齐 README、产品、架构、设计、目录、路线图和备份恢复文档。

## 设计取舍

- V1 继续采用 Go + Gin + GORM + MySQL 的 MVC 分层；标签和软删除属于资料域，不提前拆微服务。
- 软删除优先保证“删除后不可见”，物理文件清理作为补偿步骤；这样文件删除失败不会让已删除资料重新出现在列表，但需要后续孤儿文件巡检。
- Markdown 只返回安全文本，不把用户内容直接作为可执行 HTML；PDF 暂不在线渲染，避免在尚未完成内容安全评估前扩大攻击面。
- MySQL 是元数据真相源；Redis/MQ 延后到真实处理任务出现并完成基线测量之后。

- 文件系统和数据库不是同一事务，仍需孤儿文件巡检和真实恢复演练。

## 提交前复核补充

代码评审发现 MySQL DDL 不支持依赖跨语句事务回滚，已改为固定连接上的 advisory lock、逐句执行可重入迁移，并用 `INSERT IGNORE` 记录版本；`003_soft_delete.sql` 会先检查字段和索引是否存在，避免进程崩溃后重复 `ALTER TABLE`。删除接口保持“先隐藏、后清理”策略，但重复调用会返回已隐藏资料，允许在物理文件删除失败后重试。前端详情请求增加单调序号，关闭详情会使未完成请求失效。

复核后的 `go test ./...`、`go vet ./...`、`gofmt -l .`、`npm run build` 和全新隔离 MySQL 迁移/资料测试均通过。
