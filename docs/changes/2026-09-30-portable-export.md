# 2026-09-30 · 私有资料可携带清单导出

## 目的与范围

补齐路线图 P1 的可携带清单：在资料库工具栏下载当前账号的版本化 JSON，包含文件元数据与标签、外部卡片与标签、私人笔记和双向关联。不读取或打包本站原件、派生产物和第三方文件；没有导入或恢复功能。具体格式边界见 [ADR 0013](../decisions/0013-portable-metadata-export.md)。

## 设计与取舍

- Model/Repository/Service/Controller 分层：MySQL 同一只读快照按账号装载可见资料，Service 生成 `mizuki-archive-portable` v1，Controller 在完整构造成功后返回附件。空结果使用数组，关系以稳定 ID 指向两端。
- 每类条目和 JSON 总大小均有限额；超出时 413，不产生貌似完整的截断清单。30 秒超时、每用户每分钟两次、本进程最多两个并行导出；不会创建残留明文临时文件。
- 安全复核：存储键与账号 ID 在模型 JSON 中隐藏，查询全部显式限定会话身份；笔记只跟随未删除文件，关系仅当两端都属于快照时导出。备份、外部抓取与账号信息不在此接口。

## 验证与遗留

- 服务层单测：无会话拒绝、固定版本、内部字段不泄露、超大响应与仓储行数超限均有断言；HTTP 单测：匿名、两账号隔离、附件及无缓存头、413 和限流均有断言。
- 真实 MySQL 8.4 独立 `mizuki_test_portable_20260930` 数据库验证两用户隔离、文件及卡片标签、私人笔记与关系，并在删除文件和卡片后复查；完整仓储回归通过，临时库及权限已清理。
- `go test ./...`、`go vet ./...`、`npm test --prefix web`（现有 13 项）、`npm run build --prefix web` 和 `git diff --check` 通过。现有前端自动化用例没有覆盖新的下载按钮，不能把类型检查等同于浏览器验收。
- 登录后真实浏览器下载、下载文件实际查看与 320 px 窄屏、接近上限的内存和容量尚未验收；路线图保持未完成。运行中的旧 API 尚无新路由，不能把代码测试当作已部署。
- 审阅发现原生下载链接在 413/429 时会直接显示 JSON 错误，现改为页面内提示；仅成功响应创建短时 Blob URL 并下载。超大数据集目前明确拒绝，后续可评估后台分卷导出。
