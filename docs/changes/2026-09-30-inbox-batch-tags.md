# 待整理收件箱批量标签

- 日期：2026-09-30
- 目的：给当前登录用户的站内文件和外部卡片增加同一标签的批量增删，保持目录和事务边界易懂。

## 范围和取舍

- `PATCH /api/batch/tags` 接受 1–50 个不同来源/ID、一个规范标签及 `add`/`remove`；私有路由、8 KiB 请求体完整读取/拒绝尾随数据、每用户限流。Repository 在同一 MySQL 事务内锁定全部本人条目，单文件标签替换也锁定文件主行；越权/缺失/软删除/单项达到 10 标签上限时拒绝整批；重复操作幂等，响应只列真正变化的项。
- Vue 收件箱当前页可批量选择两类条目；提交前确认数量，成功后只针对真正变化的项提供一次反向操作。反向操作**不是版本化回滚**，其他设备后续更改同一标签可能被覆盖，执行前必须再次确认。
- 当前入口只在待整理收件箱，已整理资料仍可在各自详情手工编辑标签；批量收藏、归档、删除和全资料批量入口未做。大陆手机号使用已有 `+86` 规范化；真实短信发送器尚未配置，手机注册/登录不可用，本改动不触碰认证状态。

## 验证

- 服务层：先观察未实现时失败，再覆盖匿名、非法/重复选择、超量、标签规范化和错误动作；HTTP 测试覆盖匿名、混合越权、无效输入、真实变化数量和限流。
- 单独创建并停止的 MySQL 8.4 临时容器：隔离 `mizuki_test_` 库首次迁移、文件及卡片的事务增删/幂等、跨用户混合批次、软删除、标签上限和“先写文件、后卡片触顶”的回滚用例通过；测试不触碰开发库。首轮 DSN 在 PowerShell 中插值错误；一次容器尚未完成初始化导致连接 EOF，改为等待实际查询可用后最终复测通过。
- `go test ./...`、`go vet ./...`、`npm --prefix web test`（现有 11 项不覆盖此组件）、`npm --prefix web run build`、`git diff --check` 首轮与修正后最终回归均通过。安全审查发现并修复尾随请求体绕限问题，可读性审查发现并统一单文件与批量标签的行锁协议；浏览器中勾选、确认与反向恢复仍未手动验收。

## 风险与下一步

- 反向标签操作缺少记录版本或 CAS 冲突检查，且响应丢失后重试可能返回空变化项而失去原有撤销依据；现有确认对话框只提示风险，不保证跨会话安全恢复。后续如需强撤销语义，应增加操作 ID、持久结果和 409 冲突响应。
- 全部批量 TODO 仍未完成；按用户可解释的归档与删除语义逐项设计，不把标签切片冒充完整版本。
