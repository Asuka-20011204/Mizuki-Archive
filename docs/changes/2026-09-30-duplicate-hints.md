# 同账号疑似重复提醒

- 日期：2026-09-30
- 目的：保存资料时提示当前账号已存在的相同内容或链接，避免误以为系统会替用户删除原件。

## 范围与取舍

- 文件继续允许重复上传，成功落盘登记后按 SHA-256 查询同账号另一份未删除资料；只在本次保存响应附带目标 ID/名称。外部卡片创建或编辑成功后，对 HTTP(S) 地址按协议/主机大小写、默认端口、片段与查询参数顺序规范化，存摘要并按用户查询。只比较纯文本，不请求第三方，也不比较本地路径。
- 新增 `013` 迁移：在锁内补建两类用户范围索引、卡片链接摘要列，并分批回填旧卡片；中途 DDL 或回填失败可重试。迁移前仍需备份，回退应用可保留新列和索引，不应删除原有资料。
- 同账号边界由仓储显式使用服务端会话 `user_id` 实现；跨账号资料不能作为提示返回。查重故障不回滚已经保存的资料，响应告知“重复检查暂不可用”。不把疑似重复当成唯一性约束或自动清理理由。
- 大陆手机号格式/挑战基础保持现状；短信服务商、签名/模板、预算仍未确认，手机注册入口保持关闭。

## 验证

- 规范化链接单测（含编码斜杠避免误报）、服务层成功/失败分支、HTTP 带 Cookie 多账号文件与卡片响应均通过。
- 隔离 MySQL 8.4 新库首次/重复/中断重试迁移、模拟旧卡片回填、跨账号隔离、软删除与地址变更通过；临时容器已停止。
- `go test ./...`、`go vet ./...`、`npm --prefix web test`、`npm --prefix web run build`、`git diff --check` 通过。
- 前端展示已通过类型检查与构建；未用浏览器手动操作文件上传和卡片表单，不把 HTTP/构建等同于浏览器实测。

## 风险与后续

- SHA-256 相同表示文件内容相同，链接摘要相同只表示规范化地址相同，不保证站外资源本身相同；带不同提取码、重定向、短链接和动态参数可能提示不足或误判。提示不是阻止保存的条件。
- 大量历史卡片首次迁移需分批计算摘要，DDL 和回填应在维护窗口与备份后执行；用户可通过详情自行核对。下一步按路线图推进统一搜索及剩余批量操作，另行做浏览器手动验收。
