# 手动图片与扫描 PDF OCR

日期：2026-10-04。状态：手动 OCR 切片已完成隔离自动化与真实浏览器回归；不代表公网生产容量或全路线图完成。

## 目的和范围

图片和扫描件仅依赖文件名难以找回。用户在自己资料详情中手动创建 `ocr_text` 任务，由独立 Worker 对图片或扫描版 PDF 识别并生成纯文本派生产物。详情展示页数、平均置信度、下载和原件旁纯文本对照；正文参与账号范围关键词检索，原件不修改。PDF 原有文本层提取仍保留独立入口，OCR 不是上传后的自动任务。

Controller 只校验 HTTP 与处理类型，Service 校验资源归属/格式、任务幂等与派生文件写入，Repository 保存任务、正文与 `021_ocr_metadata.sql` 元数据，处理器运行受控的 Tesseract/Poppler 命令。Vue 用文本节点展示 OCR 输出，不按 HTML 执行。部署采用 API 和 Worker 分镜像目标，仅 Worker 安装识别工具。

## 关键取舍与安全边界

- 图片先验证格式与像素上限；PDF 最多 30 页，逐页渲染最长边 2200 像素，处理后立即删除该页临时图片。单页外部命令最多 45 秒，整项任务最多 2 分钟，正文不超过 10 MiB。
- OCR TSV 输出限长，丢弃外部命令 stderr；派生正文仅供私有检索，失败摘要不泄露本机路径。识别器置信度是提示，不是内容正确率；空白或失败不产生空派生文件。
- `021` 迁移可在列已创建但版本标记未写入后安全重试。上线前须备份数据库与文件目录，再用独立迁移账号升级；API/Worker 的生产运行账号不负责 DDL。
- OCR 与缩略图争用图片槽位，其他槽位仍可处理普通文本。容器 Worker 使用非 root、只读根文件系统、256 MiB `/tmp` tmpfs 与 768 MiB 内存限制；这些是保护上限，不是峰值资源测量结果。
