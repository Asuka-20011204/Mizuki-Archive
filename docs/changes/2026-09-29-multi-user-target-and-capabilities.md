# 多用户目标与认证能力探测

- 日期：2026-09-29
- 目的：纠正“个人数字信息管理”与“单用户系统”的混淆，明确项目面向多个独立用户，并把高并发、高可用定义为可验证的工程演进目标。
- 用户影响：未配置完整 SMTP 时，前端只显示兼容密码登录，不再展示不可用的邮箱登录/注册；配置 SMTP 后由服务端能力接口动态开放邮箱入口。
- 变更范围：新增 `GET /api/auth/capabilities`；新增验证码发送与核验的 Redis/单进程 IP 固定窗口限流；修复并发邮箱登录时共享认证状态导致的会话串号风险；将用户范围索引拆为可重试的 `009` 迁移；同步 README、产品、架构和路线图中的多用户、高并发、高可用边界；补充能力探测、限流和并发会话单测。
- 主要取舍：能力状态由后端配置决定，浏览器不猜测环境；本地限流只作为 Redis/入口层限流故障时的降级保护，不把单实例窗口描述成跨节点全局限流。
- 验证：`gofmt -w ...`、`go test ./...`、`go vet ./...`、`npm --prefix web run build`、`git diff --check` 均通过；`go test -race` 因当前环境 `CGO_ENABLED=0` 未执行成功，不能据此宣称竞态验证完成。
- 已知限制：`007`–`009` 真实隔离 MySQL 兼容迁移、跨用户 HTTP 越权负例、真实 SMTP 浏览器注册闭环、多 API/Worker 节点和组件集群故障切换仍未验收。
- 下一步：先验证旧库迁移和 A/B 用户资料、任务、派生产物隔离，再补真实 SMTP 浏览器流程；之后以混合负载做多实例容量和高可用演练。
