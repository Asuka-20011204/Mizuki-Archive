# 资料检查器布局调整

## 目的

把资料详情从一条功能堆叠的长抽屉调整为更接近 Windows 属性面板和企业资料系统的检查器，降低单击打开详情后的信息密度和操作负担。

## 范围

- 资料列表行继续使用单击打开详情，并补充可访问名称，明确这是查看入口。
- 桌面端详情采用“预览与处理主区 + 属性与操作侧栏”的双栏结构。
- 窄屏详情改为全屏单列，主区与侧栏上下分隔，避免横向挤压和页面溢出。
- 更新设计文档，明确检查器的信息层级；不改变 API、权限、数据结构和现有业务操作。

## 设计取舍

- 参考 Windows 属性面板的“先看内容、再看属性与动作”层级，但不复制系统视觉或素材。
- 保留当前明亮的 Mizuki/Sakurairo 视觉方向，只借用企业系统的密度和分区方式。
- 不引入双击打开、右键菜单或新的快捷键，避免改变个人资料库已有的单击习惯。

## 验证结果

- `npm run build --prefix web`：通过（包含 `vue-tsc --noEmit` 和 Vite 构建）。
- `git diff --check`：通过；仅有 Git 的 LF/CRLF 提示。
- 浏览器桌面与无预览格式：已在 `http://127.0.0.1:5180/` 合成预览中检查；窄屏与真实 API 回归仍待执行。

## 遗留风险与下一步

- 详情中的真实预览、标签保存、文本任务和删除，以及窄屏滚动仍需在本地 API 登录后按启动文档回归。
- 若后续需要跨设备访问，应单独设计 HTTPS 反向代理和监听地址配置，不与本轮视觉调整混合。
