# 多用户产品定位纠偏与隔离验收更新

- 日期：2026-09-29
- 目的：明确“个人数字信息管理”是产品领域和资料使用场景，不是“只有一个人使用”的部署约束；系统面向多个独立用户，并以用户归属作为资料、会话和处理能力的服务端权限边界。
- 用户影响：不同用户可以注册并使用系统，但默认只能看到、下载、收藏、删除和处理自己的资料；系统当前不提供跨账号共享。首位用户仍可作为项目作者的迁移对象，但不享有绕过归属校验的特殊资料权限。
- 文档范围：更新 `AGENTS.md`、`README.md` 和 `docs/roadmap.md` 的当前口径；保留早期变更记录中的历史设计上下文，避免把历史提案改写成当前事实。
- 验收更新：隔离 MySQL 8.4 已验证 `001`–`009` 首次执行和重复执行；补充跨用户资料读取、下载、收藏和删除的 HTTP 负例。任务、派生产物、真实旧库回填和真实 SMTP 浏览器闭环仍未完成。
- 高并发/高可用边界：多用户能力是当前产品边界；高并发、高可用是后续生产化目标。多 API、多 Worker、MySQL 高可用、Redis Sentinel/Cluster、RabbitMQ 集群、共享文件存储和持续混合负载仍需独立验收，不能用本机测试结果替代。
- 下一步：完成任务与派生产物跨用户越权测试，执行真实旧库回填演练；准备 SMTP 测试环境后完成多账号浏览器注册、登录、退出和资料隔离闭环。
