# 验证码入口与资料详情体验修复

- 日期：2026-10-04
- 目的：消除“验证码请求已受理就是未知账号登录成功”的误解；减少资料详情中的功能堆叠。

## 改动与取舍

- 保持服务端注册/登录挑战用途隔离和未知账号统一受理，防止账号枚举；补充未知邮箱与手机号无法获得会话的 HTTP 断言。新账号通过显式注册码核验，并一次写入唯一用户名和 bcrypt 密码哈希；普通用户可通过用户名/已验证联系方式加密码登录。既有无密码账号仍可使用验证码登录，不擅自替其生成密码。
- 登录页面改为注册/登录流程选择加单个邮箱/大陆手机号输入框；注册须设置用户名、密码和确认密码，密码登录是普通用户及兼容管理员共用的次级入口。按服务端能力启用身份类型，当前未接短信禁用手机验证码，输入或流程切换清除旧码。不合并手机号和邮箱账号。
- 详情默认仅显示原件预览、属性、下载与收藏；名称、标签、笔记和关联归“整理与关联”，任务和产物归“按需处理”。保留笔记草稿组件实例、相邻资料导航和安全下载；删除收入“更多操作”。OCR 展开时原件与文本同屏对照。
- 前端没有从验证码请求的 202 判断用户是否存在，也不根据用户输入创建资料命名空间。现有 `users.password_hash` 与用户名唯一约束可直接使用，无需新迁移；注册接口新增必填的 `username`/`password`，旧的无密码注册请求会返回 400，需更新既有客户端。

## 验证与遗留风险

- `go test ./...`、`go vet ./...`、前端类型检查/构建、前端 20 项测试及 `git diff --check` 通过。新增注册字段校验、密码哈希验证、密码成功/失败及未知账号拒绝的 Go 用例通过；隔离 MySQL 用例因未配置 `MIZUKI_TEST_MYSQL_DSN` 跳过，不宣称实库完成。
- 浏览器本地 5173 合成未知邮箱请求得到统一提示，使用假验证码无法进入；未接入手机号有明确提示，窄屏注册/登录主选项无横向滚动。新增用户名、密码和确认密码输入、普通密码入口可见；重启 API 后 `/healthz` 返回 204，使用无效注册字段得到新版本 400，合成未知账号密码登录得到统一错误。
- 登录后的真实资料详情三分区、键盘和窄屏交互仍需用隔离测试账号进行浏览器验收；未在正式资料库创建测试账号，也未测试真实邮件/短信投递。
- 后续接入短信供应商时须增加预算、共享限流、隐私留存与真实浏览器回归；如需邮箱/手机号绑定同一账号，必须另设计双端验证与迁移流程。
- 旧无密码账号若要密码登录，还需在已认证会话内设计单独的安全补设流程；目前不允许未经核验直接认领账号。邮箱或手机号注册均不授予管理员角色；现有管理员仍是环境凭据兼容身份，不等同于 RBAC 管理功能。
