# 外部卡片更新成功语义修复

- 日期：2026-09-30
- 目的：避免数据库更新已提交、随后读回失败却向用户报告“保存失败”。

## 范围与取舍

- `UpdateExternalResource` 在同一事务内验证账号归属、更新可编辑字段、替换标签并读回带创建时间与整理状态的完整卡片。任一环节失败会回滚；Service 不再在事务提交后做必需的第二次读取，重复提醒仍可按原约定降级。
- 继续将归属条件绑定到数据库行，不信任前端传来的创建时间与整理状态；用户可见 API 返回结构不变。只调整卡片更新契约，不改变上传文件和删除行为。
- `013` 迁移的滚动升级注意事项写入部署文档：停止旧实例写入后再运行迁移，并核查遗留空链接键；不以删除卡片清理历史。

## 验证与遗留

- 服务层先新增“更新成功后普通读取失败”测试并观察旧实现失败，再修改事务边界；随后服务、控制器和仓储测试通过。
- 隔离 MySQL 8.4 的 `TestExternalResourceMySQLIsolation`、`TestDuplicateMySQLIsolation` 均通过，临时容器已停止；测试覆盖事务内返回标签、整理状态、跨用户更新拒绝和更新链接键。`go test ./...`、`go vet ./...`、`git diff --check` 通过。
- 自查归属条件始终使用已验证会话用户；标签读回在事务内，任何读回错误均在提交前返回，防止已提交后误报失败。浏览器更新卡片的故障注入场景未手工实测，数据库提交失败等极端不确定结果未进行网络断链故障演练。
