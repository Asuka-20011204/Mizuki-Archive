# 批量归档与找回

- 日期：2026-09-30
- 目的：让多用户资料库中的文件和外部资源卡片暂时退出活动视图，并能由所属用户明确找回，不误删原件。

## 范围与取舍

- `016` 迁移增加两表的可空 `archived_at` 及用户范围索引；在迁移锁内检查已建列，允许 DDL 完成但版本登记中断时重试。生产迁移前须先备份。
- `GET /api/archive` 按会话用户分页列出两类归档资料；`PATCH /api/batch/archive` 要求 1–50 个不同的来源/ID 与明确目标，事务内先锁定核验全部本人条目，再只写入实际变化，返回 `changed/count`。跨用户、缺失或软删除文件整批拒绝。
- 活动文件/卡片列表、统一搜索、待整理收件箱及最近查看不显示归档项，私有详情和下载仍遵守账号归属；归档不修改原件、标签、整理状态和卡片链接状态。
- 前端待整理收件箱确认归档并提供单次恢复，归档区分别显示两类条目、当前页最多选择 50 项并确认恢复；操作后同步刷新活动视图。Sakurairo 仅用于现有布局/视觉参考，没有复制主题资产。
- 用户确认手机号仅限中国大陆：接受 11 位号码或 `+86` 前缀，标准化存储 `+86` 加 11 位；真实短信提供方仍未确定，手机注册/登录继续关闭。

## 验证

- 归档服务和 HTTP 测试覆盖输入、身份、跨账号混合批次、重复目标与受限请求；仓储测试覆盖首次/重复及迁移中断恢复、账号隔离、活动列表与归档列表切换。先前在独立 MySQL 8.4 `mizuki_test_*` 库的 `TestArchiveMySQLIsolation` 已通过。
- 本轮 `go test ./...`、`go vet ./...`、`npm --prefix web run build` 和 `npm --prefix web test`（11 项）通过。独立临时 MySQL 8.4 中的 `go test ./internal/repository -count=1` 全量回归通过，容器已停止；现有前端测试未覆盖归档组件交互，浏览器人工实测待进行。

## 风险与下一步

- 响应丢失后重试可能得到空变化项；反向操作若与另一设备修改冲突，会覆盖新状态。若需可靠撤销，需要持久操作 ID 和版本冲突检测。
- 本切片尚未覆盖已整理资料的批量归档入口、批量删除/恢复方案；需要浏览器核对键盘选择、窄屏、归档后搜索/卡片更新，再继续 P0。手机号认证须另选真实短信提供方、签名/模板与预算后验收，不能把基础服务代码标为已开放。
