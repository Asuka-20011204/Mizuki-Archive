# 2026-09-29 · V3 异步队列与 V4 Redis

## 目的与范围

在个人数字信息管理的手动处理任务上加入可回滚 RabbitMQ 投递路径；以 Redis 加速可重建元数据、记录最近访问并提供共享限流。保持 Go MVC/Service/Repository 分层和默认数据库模式，没有新建通用任务平台。

## 取舍与安全

- `005` 迁移增加事务 Outbox 并回填旧任务；发布确认、租约领取、ACK 后置、定期补偿和异常消息隔离确保至少一次处理，不承诺恰好一次。
- 发布通道异常重建；崩溃重领不超过最大执行次数。消息只含任务 ID，不能携带私有文件。
- 私有资料列表不缓存，避免软删除与并发缓存回填竞态；任务/标签缓存短 TTL，详情/下载权限回源数据库。最近访问仅 ID、20 条上限、90 天到期，删除时尽力清理。
- Redis 故障时回源 MySQL；登录保留单机失败次数保护，但跨进程限流失效。Compose 可选容器必须设置非空密码；Redis 密码不作为进程命令参数。
- 前端新增最多五项的“最近查看”快捷入口；登录/刷新/查看/删除同步状态，退出后使在途请求失效。

## 已执行验证与遗留

- 隔离 MySQL 8.4：迁移首次/重复执行、任务与 Outbox 同事务、重复请求、发布后旧租约拒绝、丢失事件修复、崩溃次数耗尽通过；测试库已清理。
- 使用独立 Docker 项目及临时凭据，RabbitMQ 持久发布确认/消费 ACK、Redis JSON 读写、共享限流和最近访问删除集成测试通过；测试容器与卷已清理。首次主机 `6379` 绑定因 Windows 保留端口失败，改为默认 `6381` 后重跑通过。
- 隔离 MySQL + RabbitMQ + Redis 的完整任务链验证了手动触发、发布、消费、派生文件、重复消息幂等及 Redis 故障回源。真实 Broker 停机期间提交任务保持 `pending`，重启后自动完成（1 次处理）；模拟 Worker 崩溃的过期租约由定期补偿重新投递并在第 2 次处理成功。
- 真实 Broker 连续 4 次模拟失败后，消息在约 7 秒退避后进入死信队列；非法消息头的单元测试验证了负数与越界拒绝。
- 隔离浏览器回归：测试账号登录、上传合成 TXT、手动提取、完成状态/派生下载入口、正文关键词检索、最近查看入口。Redis 停机并刷新后登录态、列表、详情、任务与下载入口仍可用，最近查看按设计隐藏；重启恢复。
- 同一台本地机器、单任务已成功后，100 次串行任务详情读取：不接缓存 MySQL 路径 1.017 秒，Redis 短缓存路径 0.584 秒。此数字包含 Redis 路径逐次的 MySQL 资料可见性核验，是一次本地样本，**不是**并发吞吐/生产承诺；用例可在设置隔离测试 DSN 后重跑。
- V7 仍需固定数据集并发压测、基线/优化多轮对比及瓶颈归因；暂不推断真实负载下收益。浏览器回归使用合成资料与隔离库，不含真实个人文件。
- V7 需固定负载比较基线与收益，不填写假数字。仓库外全局设置发现疑似明文认证令牌，须撤销轮换；本文不记录值。

## 2026-09-30 · 投递模式回归

- 数据库模式只更新待处理任务，不写 RabbitMQ 重试事件；Rabbit 模式由 API 启用事务创建事件、API/Worker 共同启用仓储重试事件，切换模式时须同步重启两端。
- 新增三依赖真实处理链的隔离测试；重复消息只产生一个派生文件，Redis 故障时回源 MySQL。首次并行运行不同测试包时服务用例失败（未保留完整错误，不能断定原因）；单包复测通过，再以 `go test -p 1 -count=1 -v ./internal/service ./internal/repository ./internal/queue ./internal/cache` 顺序运行通过。共用测试库时建议顺序执行，后续排查并行失败原因。临时测试容器已清理，未改动本地开发库。
- `go test ./...`、`go vet ./...`、`gofmt -l cmd internal` 和前端类型检查/构建通过。该集成用例不覆盖生产负载，V7 仍需独立压测。
