# 2026-09-29 · V3 异步队列与 V4 Redis

## 目的与范围

在个人数字信息管理的手动处理任务上加入可回滚 RabbitMQ 投递路径；以 Redis 加速可重建元数据、记录最近访问并提供共享限流。保持 Go MVC/Service/Repository 分层和默认数据库模式，没有新建通用任务平台。

## 取舍与安全

- `005` 迁移增加事务 Outbox 并回填旧任务；发布确认、租约领取、ACK 后置、定期补偿和异常消息隔离确保至少一次处理，不承诺恰好一次。
- 发布通道异常重建；崩溃重领不超过最大执行次数。消息只含任务 ID，不能携带私有文件。
- 私有资料列表不缓存，避免软删除与并发缓存回填竞态；任务/标签缓存短 TTL，详情/下载权限回源数据库。最近访问仅 ID、20 条上限、90 天到期，删除时尽力清理。
- Redis 故障时回源 MySQL；登录保留单机失败次数保护，但跨进程限流失效。Compose 可选容器必须设置非空密码；Redis 密码不作为进程命令参数。

## 已执行验证与遗留

- 隔离 MySQL 8.4：迁移首次/重复执行、任务与 Outbox 同事务、重复请求、发布后旧租约拒绝、丢失事件修复、崩溃次数耗尽通过；测试库已清理。
- 使用独立 Docker 项目及临时凭据，RabbitMQ 持久发布确认/消费 ACK、Redis JSON 读写、共享限流和最近访问删除集成测试通过；测试容器与卷已清理。首次主机 `6379` 绑定因 Windows 保留端口失败，改为默认 `6381` 后重跑通过。
- Broker 崩溃/重复消息、Redis 故障降级、浏览器端完整 V3/V4 回归与基线对比仍未执行；不把未执行项标为通过。
