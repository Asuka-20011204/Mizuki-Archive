# 多来源统一搜索

- 日期：2026-09-30
- 目的：把已上传文件、手动标签、卡片备注及成功提取的正文汇入一个可信的私有搜索入口。

## 范围与取舍

- `GET /api/search?q=...&page=...` 在 Cookie 会话下只查当前用户，文件与外部卡片分组各取最多 20 项、分别提示是否有下一页；结果不混淆站内原件和仅存线索的卡片。
- 文件搜索涵盖展示名、原文件名、手动标签和派生文本；外部卡片搜索涵盖标题、地址、类型、版本、备注及标签。正文和数据库路径不返回前端。查询限制 1–100 字符、拒绝控制字符、页数不超过 1000，返回稳定排序；SQL 使用参数绑定，卡片 LIKE 对通配符做字面转义。无效输入会使在途前端搜索响应失效，避免旧结果重新出现。
- 服务、控制器、仓储各守其边界；Vue 使用单独面板，不把复杂搜索逻辑塞进现有文件列表。复用项目自有 Sakurairo 风格设计 token；独立文件笔记/摘录仍在 P1，不视为已实现。
- 搜索按账号每分钟最多 30 次，共享 Redis 限流与单实例兜底并行；每次数据库查询最多 5 秒，超时明确报错，不把返回条数上限误当作扫描成本上限。搜索开始即清除上次结果，避免失败后旧结果伪装新命中；结果操作按钮的可访问名称包含资料标题。

## 验证

- Go 服务层输入/分页/控制字符单测、HTTP 会话/跨账号/限流负例和隔离 MySQL 8.4 标签/备注/提取正文/软删除/通配符测试通过；临时数据库容器已停止。
- `go test ./...`、`go vet ./...`、`npm --prefix web test` 和 `npm --prefix web run build`：提交前已通过；差异及暂存区检查在提交前执行。仓储隔离 MySQL 验证发生在追加限流/控制字符修复之前，后续仅改服务/HTTP/View，不把它冒充修复后的数据库复测。真实浏览器点击搜索、详情与窄屏样式**尚未**手动验收，不以类型检查或 HTTP 测试替代。
- 代码与安全复查发现模糊查询可能被高频调用、失败时旧结果残留、操作按钮读屏名称不清；已补账号限流、5 秒超时、旧请求失效/旧结果清除及可访问名称，并补跨账号限流测试。未测量大数据规模下的查询耗时。

## 风险与后续

- `LOCATE` 和模糊 `LIKE` 在用户数据增长时可能扫描较多行，20 项返回窗口不等于执行成本上限；上线前用真实规模记录耗时、评估分词/全文索引与限流。
- 搜索结果在并发写入时，基于 offset 的分页可能重复或遗漏；未来数据规模上升时评估游标。下一步继续路线图剩余批量操作与保存检索视图；手机号真实短信仍待服务商/签名模板/费用确认。
