# 分期路线图

阶段是学习与交付顺序，不是已经完成的功能；每阶段必须有演示场景、测试与可回退路径。不要在前一阶段未稳定时同时引入全部基础设施。

| 阶段 | 用户价值 | 工程交付与退出条件 |
| --- | --- | --- |
| V0 定义 | 明确资料范围与使用路径 | 产品边界、架构提案、安全与 Git 规范，确认首期身份/备份/文件限额。当前仅完成文档草案。 |
| V1 可用资料库 | 上传、手动整理、搜索、查看、下载 | Go API + MySQL + 本地受控存储 + 前端；认证、异常/空状态、文件校验、迁移、备份恢复演练；关键路径测试。 |
| V2 处理闭环 | 资料处理可见、失败可追 | [已完成首个切片] MySQL 持久任务 + 单 Worker；手动 PDF/TXT/Markdown 文本提取和图片缩略图、状态、租约、派生文件下载/预览和关键词检索。 |
| V3 异步队列 | 批量处理不拖慢请求 | [实现中] RabbitMQ、事务 Outbox、发布确认、幂等消费、ACK、有限重试/隔离队列；真实崩溃及重连演练仍需完成。 |
| V4 热点优化 | 常用资料与任务状态查询更稳定 | [实现中] Redis 短缓存/限流/最近访问；故障降级与基线/优化对比仍待验证，私有资料列表不缓存。 |
| V5 并发控制 | 多任务提交时系统仍可用 | Worker Pool、背压与资源配额；基于真实负载数据调整并发度，验证积压、超时和重启恢复。 |
| V6 部署 | 可重复部署和恢复 | Docker 本地部署、健康检查、备份演练、最小权限；Kubernetes 仅作为可选练习而非生产必需。 |
| V7 量化 | 有证据解释架构取舍 | 固定数据集与环境压测、基线/优化对比、瓶颈与成本记录；如实记录数字和限制。 |
