# 分期路线图

阶段是学习与交付顺序，不是已经完成的功能；每阶段必须有演示场景、测试与可回退路径。不要在前一阶段未稳定时同时引入全部基础设施。

| 阶段 | 用户价值 | 工程交付与退出条件 |
| --- | --- | --- |
| V0 定义 | 明确资料范围与使用路径 | 产品边界、架构提案、安全与 Git 规范，确认首期身份/备份/文件限额。当前仅完成文档草案。 |
| V1 可用资料库 | 上传、手动整理、搜索、查看、下载 | Go API + MySQL + 本地受控存储 + 前端；认证、异常/空状态、文件校验、迁移、备份恢复演练；关键路径测试。 |
| V2 处理闭环 | 资料处理可见、失败可追 | 持久任务 + 单 Worker；先选一个确能验证的处理类型，补状态机、超时、失败处理、重试与产物记录；不显示虚假的进度。 |
| V3 异步队列 | 批量处理不拖慢请求 | RabbitMQ 替换任务投递路径；事务性 outbox/等效方案、发布确认、幂等消费、ACK、有限重试/隔离队列；验证进程崩溃与重复消息。 |
| V4 热点优化 | 常用资料与任务状态查询更稳定 | Redis 缓存/有界限流/最近访问；比较基线、失效与降级，不为缓存牺牲私有数据隔离。 |
| V5 并发控制 | 多任务提交时系统仍可用 | Worker Pool、背压与资源配额；基于真实负载数据调整并发度，验证积压、超时和重启恢复。 |
| V6 部署 | 可重复部署和恢复 | Docker 本地部署、健康检查、备份演练、最小权限；Kubernetes 仅作为可选练习而非生产必需。 |
| V7 量化 | 有证据解释架构取舍 | 固定数据集与环境压测、基线/优化对比、瓶颈与成本记录；如实记录数字和限制。 |

## 下一步首个开发切片

1. 与用户确认 V1 的登录方式、允许格式与上传上限、私有资料存储/备份位置。
2. 建立 Go API、数据库迁移、Vue 前端与最小测试/CI；先实现认证下的单文件上传 → 列表 → 详情 → 下载闭环。
3. 在安全检查通过后，再增加标签、筛选、删除；每步更新真实 README 命令和验收状态。

面试表述遵循“真实问题 → 测量 → 取舍 → 结果”。博客/内容管理经验提供起点，个人资料库是独立的资料处理场景；不得把计划中的 MQ、Redis 或性能结论写成已完成经历。

## 当前 V1 状态（2026-09-29）

已写入单管理员会话、上传、文件名/类型筛选、详情、下载和收藏状态编辑。收藏已通过 Go HTTP/Service 测试与隔离 MySQL 实库测试；此前登录、上传、下载流程的实库及窄屏浏览器验证见变更记录，收藏按钮尚未做浏览器实测。V1 仍缺标签、名称编辑、预览、删除、备份恢复演练、迁移版本跟踪与覆盖率目标，不可标为完成。
