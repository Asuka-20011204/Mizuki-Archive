# 分期路线图

阶段是学习与交付顺序，不是已经完成的功能；每阶段必须有演示场景、测试与可回退路径。多用户隔离、高并发和高可用是贯穿全路线的目标，不因分阶段交付而降级为“以后可能做”。不要在前一阶段未稳定时同时引入全部基础设施。

| 阶段 | 用户价值 | 工程交付与退出条件 |
| --- | --- | --- |
| V0 定义 | 明确资料范围与使用路径 | 产品边界、架构提案、安全与 Git 规范，确认首期身份/备份/文件限额；文档已随 V1 实现更新。 |
| V1 可用资料库 | 多个独立用户分别上传、整理、搜索、查看、下载自己的资料 | Go API + MySQL + 本地受控存储 + 前端；认证与归属隔离、异常/空状态、文件校验、迁移、备份恢复演练；关键路径测试。 |
| V2 处理闭环 | 资料处理可见、失败可追 | [已完成首个切片] MySQL 持久任务 + 单 Worker；手动 PDF/TXT/Markdown 文本提取和图片缩略图、状态、租约、派生文件下载/预览和关键词检索。 |
| V3 异步队列 | 批量处理不拖慢请求 | [已验收] RabbitMQ 事务 Outbox、发布确认、幂等消费、ACK、有限重试/死信；Broker 停启及过期租约恢复、重复消息实测。 |
| V4 热点优化 | 常用资料与任务状态查询更稳定 | [已验收] Redis 短缓存、共享限流、最近访问；故障回源及同环境对照已实测，私有资料列表不缓存。 |
| V5 并发控制 | 多任务提交时系统仍可用 | [核心机制已验证] 有界 Worker Pool、持久任务容量门禁、429 背压、过期租约接管；真实负载下的并发度调整留待 V7。 |
| V6 部署 | 可重复部署和恢复 | [单机隔离演练通过] Docker 本地部署、就绪检查、备份/恢复、非 root 与受限端口；公网生产加固仍单独规划。 |
| V7 量化 | 有证据解释架构取舍 | [本地固定负载已测] 任务处理优化前后与 Worker 数量对比、带鉴权列表并发读取，记录瓶颈、资源成本和适用限制。 |

## 已完成的 V1 验收切片

1. 已完成兼容管理员认证、上传、列表、详情、下载和收藏；多用户身份迁移和归属隔离在同一条主线上继续收敛。
2. 已完成展示名称、手动标签、标签筛选、图片/文本预览和删除闭环。
3. 已完成 4 个版本迁移、重复迁移保护、隔离 MySQL 集成测试和备份恢复操作文档。
4. 已完成真实资料浏览器回归，并将备份恢复的实际结果追加到 `docs/changes/`。
## 当前 V1 状态（2026-09-29）

V1 基础资料能力与验收已完成。2026 年 9 月 29 日已完成真实浏览器回归（包括文件上传入口）、以及一次独立 MySQL/文件目录备份恢复演练。基础回归覆盖兼容管理员登录/退出、私有上传、名称编辑、手动标签、标签筛选、收藏、关键词/类型筛选、详情、安全预览、下载和删除；多用户身份迁移、服务端归属隔离和共享状态基础已在此基础上继续收敛。数据库迁移版本已扩展到 `001`–`009`，重复启动不会重复建表或重复执行已记录迁移。

## V3/V4 验收（2026-09-29）

- [x] 隔离 MySQL 8.4 的 `005` 迁移、任务+Outbox 原子性、重复提交、旧租约拒绝、已发布事件修复和执行次数上限。
- [x] 真实 RabbitMQ 发布确认、消费者 ACK、有限重试后死信；隔离任务链的重复消息只生成一份派生物。
- [x] Broker 运行中停启、停机期间手动提交任务并在恢复后自动完成；人为构造的 Worker 崩溃过期租约经定期补偿后重新处理。
- [x] Redis 缓存、共享限流和最近访问的真实集成测试；停止 Redis 后浏览器仍可读取私有资料和任务状态，最近访问区块降级隐藏。
- [x] 浏览器隔离库实测登录、手动文本提取、状态完成、派生产物入口、正文关键词检索和最近查看入口。
- [x] 同环境基线/缓存读路径对比，记录方法与限制于 [变更记录](changes/2026-09-29-v3-v4-queue-cache.md)；V7 才进行系统化压测。

## V5 并发控制（2026-09-29）

- [x] 数据库 Worker Pool 默认 2、可配置 1–4；RabbitMQ prefetch 不超过 Worker 数，停机取消后等待已启动处理退出。
- [x] 新迁移 `006` 加入全局容量锁；同一事务识别重复任务、限制 `pending + processing` 总数并写入任务及可选 Outbox。满额返回 `429 queue_full` 和 `Retry-After: 5`。
- [x] 独立 MySQL 8.4 库验证 5 个并发请求只接收 2 个、容量释放后再次接收、Outbox 原子性和 Worker 重启接管过期租约。
- [x] V7 使用 24 个 128 KiB 合成文本任务对比满积压排空耗时与 Go 堆峰值；单/双 Worker 均有优化前后数据。默认 2 个槽位仍是混合任务的保守选择，不将小文本结果推广到 PDF/图片。
- [x] 独立空库的合成 PDF/3000×3000 PNG 混合负载已测：双 Worker 更快但抽样 Go 堆峰值明显上升；详见 [V7 记录](changes/2026-09-29-v7-fixed-workload.md)。
- [ ] 限制高内存图片并行数、测容器 RSS 和跨进程重启恢复耗时，再确定生产并发度。

## V6 单机部署（2026-09-29）

- [x] 前后端镜像构建成功，四服务独立 Compose 项目启动；Web 仅本地 18080 对外开放，API、Worker 与 MySQL 无宿主端口。
- [x] 登录、资料上传/下载、匿名 401、前端 200、存活/就绪 204；冻结写入后备份 MySQL 与文件卷，在另一项目恢复并验证 SHA-256 一致。
- [x] 恢复实例登录、列表、下载、手动文本提取、Worker 完成及正文关键词检索通过；运行时服务非 root 且只读根文件系统。
- [ ] 生产前需拆出单独迁移账号、TLS/网关限流、密钥托管和镜像漏洞扫描；本编排只对本机环回地址开放。

## V7 固定负载（2026-09-29）

- [x] 24 个 128 KiB 合成文本任务排满数据库队列，比较优化前每次领取后休眠与优化后仅在空闲时轮询；每组单 Worker/双 Worker，优化后另独立重复三次。
- [x] 24 条合成资料、10 并发、100 次带 Cookie 的资料列表请求独立重复三次；记录请求成功率、p50/p95 和总耗时。
- [x] 明确测试机器、MySQL/Go 版本、采样范围、资源成本和无法从此推断的生产能力；原始数据与解释见 [V7 记录](changes/2026-09-29-v7-fixed-workload.md)。
- [ ] 后续如上线或更换机器，补充带 TLS/反向代理的持续并发和 PDF/图片混合负载，重新做容量规划。

## V8 多用户身份与验证码（代码基础与隔离验收已完成，真实邮件环境验收进行中）

- [x] 实现单独的 SMTP 邮件适配器并接入邮箱认证：强制 TLS，拒绝非法邮件头；本地模拟服务器覆盖 TLS 降级和加密交付。
- [x] 确认“个人”描述产品领域，不限制使用人数；允许多个独立用户注册，各自拥有私有资料空间，默认不做跨账号共享。
- [x] 完成旧管理员、资源、会话的归属迁移基础；资源、任务、派生物和 Redis 命名空间按用户边界过滤，并补充能力探测与本地 IP 限流。
- [x] 实现服务端生成、限时、限次、邮箱重发冷却、IP 限频、HMAC 摘要和原子一次性消费；失败响应不枚举账号。
- [x] 在隔离 MySQL 8.4 验证 `001`–`009` 的首次启动、重复启动和当前旧表结构兼容；补充资料读取、下载、收藏和删除的跨用户 HTTP 越权负例。
- [x] 通过真实 GORM/MySQL 隔离测试验证任务、派生产物沿资源归属链隔离；邮箱注册、一次性验证码消费、退出和再次登录的 HTTP 闭环已通过测试发送器验收。
- [x] 通过隔离 MySQL 验证旧归属空值回填和重复执行；通过隔离 Redis 验证最近访问按用户命名空间隔离。
- [x] 将邮箱验证码配置接入独立部署 API，SMTP 凭据和验证码密钥不传给 Worker。
- [ ] 配置真实 SMTP 完成浏览器注册、登录、退出和资料隔离闭环；手机号短信由提供方、成本和合规确认后再选。

身份方案与现有数据风险见 [ADR 0007](decisions/0007-verified-identity-boundary.md)。多用户代码基础、迁移兼容和资料 HTTP 隔离已完成；真实 SMTP、多账号浏览器注册闭环、任务/派生产物负例和旧库回填演练未完成前，不宣称 V8 全部完成。

## 后续产品 TODO（未实现）

以下条目是 V6 之后的产品候选，按“先提高日常效率，再形成产品特色”的顺序排列。它们只是规划，不代表当前代码已经支持。

### P0：收录、整理与找回

- [ ] **外部资源索引**：允许创建不上传原文件的资源卡片，记录百度网盘、其他网站或本地位置、资源类型、版本、标签、备注和链接状态。
- [ ] **粘贴即收录**：粘贴分享链接或一段网盘信息后预填资源卡片，用户确认后保存；不自动登录、抓取或下载第三方网盘内容。
- [ ] **待整理收件箱**：新上传或新建的外部资源先进入待整理状态，避免录入时必须填写完整信息。
- [ ] **批量操作**：支持批量加标签、收藏、修改整理状态、归档和删除，并提供明确的数量与撤销提示。
- [ ] **重复提醒**：上传文件按哈希、外部资源按规范化链接提示疑似重复；默认只提醒，不自动删除。
- [ ] **统一搜索**：在一个搜索入口中查找站内文件、外部资源、标签、笔记和已提取正文，并清楚区分资源来源。
- [ ] **保存的检索视图**：保存关键词、类型、标签、状态和来源组合，例如“待玩的游戏”“课程 PDF”“尚未整理”。

### P1：阅读与维护体验

- [ ] **快速预览与键盘切换**：详情预览中支持上一项、下一项、关闭和下载等键盘操作，减少反复打开列表项。
- [ ] **资源状态维护**：外部资源支持“可用、待确认、链接失效、已下载”等手动状态，避免把过期链接误认为可用资源。
- [ ] **资料笔记与摘录**：为资料或 PDF 页码添加私人注记、摘录和来源说明，并允许搜索笔记内容。
- [ ] **关联线索**：将游戏、攻略、截图、安装说明、存档说明等条目互相连接，先用清晰的关联列表，不引入复杂关系图。
- [ ] **可携带导出**：导出外部资源、标签、笔记、关联关系和文件清单；与现有备份区分，避免把第三方文件误认为已备份。

### P2：特色展示

- [ ] **专题展页**：把一组资源编排成有封面、简介、顺序和分区的主题页面，例如“我的游戏收藏”或“某门课程资料”。
- [ ] **扫描件 OCR**：为扫描版 PDF 和图片生成可检索文本；需要展示识别质量、失败原因和原文对照，不把 OCR 结果当作绝对准确内容。

明确不纳入本轮 TODO：**资料重逢**推荐功能。后续若需要“重新发现”体验，应先基于真实使用数据评估，不主动增加打扰式推荐。
