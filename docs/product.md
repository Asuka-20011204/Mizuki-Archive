# 产品定义（草案）

更新：2026-09-29。此文档定义意图而非实现状态；实现与验收结果随后逐项更新。

## 一句话定位

Mizuki Archive 是供个人长期管理数字资料的资料库：将 PDF、图片、Markdown/TXT 统一收纳、整理、检索，并在需要时对资料做可追踪的后台处理。

## 用户与问题

- 首位用户：项目作者本人。可扩展目标人群是积累大量课程资料、技术文档、图片或创作素材的个人；不以团队共享为首期目标。
- 问题：散落在目录里的文件难以按主题找回；预览/文本提取等处理耗时，直接放在上传请求中会拖慢交互；处理结果与失败原因容易丢失。
- 产品价值：不是重新实现云盘同步，而是把**资料的上下文、查找和处理历史**留在一起。

## 核心流程

1. 上传资料 → 校验并保存文件 → 记录名称、类型、大小、哈希、时间等元数据。
2. 人工设置标签/收藏 → 按关键词、类型、标签和时间筛选 → 查看详情或下载原件。
3. 请求处理 → 返回任务标识 → 后台处理 → 在资料详情/任务中心查看状态、结果和失败原因。

V1 实现前两步；第三步按路线图迭代。未经验证不承诺 PDF 页数、OCR、Markdown 转换或自动分类一定可用。

## V1 范围与验收

| 能力 | 首期验收口径 |
| --- | --- |
| 单人访问 | 采用单管理员和可撤销的数据库会话；私有资料不可匿名读取；实库端到端仍需验证。 |
| 上传 | 仅允许 PDF、PNG/JPEG/WebP、Markdown、TXT；单文件上限 50 MiB；服务端校验体积与类型，失败不留下可访问的半成品。 |
| 整理 | 可编辑展示名称、手动标签和收藏，能删除资料并明确文件/记录的一致性行为。 |
| 查找 | 可按名称关键词、类型、标签和时间分页筛选；有空结果与异常状态。 |
| 查看 | 能查看元数据和支持范围内的安全预览，能下载原件；不支持的类型提示下载而非危险内联渲染。 |

## 不做与待确认

- 首期不做：网盘同步、多人协作/共享、社交、AI 自动分类、音视频、Office 全格式、OCR、分布式微服务和 Kubernetes 生产部署。
- 待确认：正式部署的文件存储位置与备份策略、Markdown 是否允许富文本渲染、首个异步处理类型的输出质量标准、是否需要全文搜索。
- 设计中的吞吐与性能只作为后续实测假设，不能作为简历中的既成成绩。
