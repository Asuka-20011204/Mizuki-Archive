# ADR 0003：手动标签与标签筛选设计

- 日期：2026-09-29
- 状态：提案，待实现前复核

## 背景

当前 V1 已支持资料上传、文件名/类型检索、详情、下载和收藏，但“整理”仍主要依赖文件名。个人资料库需要一种低成本、可重复的上下文标记，让课程、面试、项目、待复习等资料可以被再次找回。标签属于元数据，不应修改原文件，也不需要 Redis 或消息队列。

## 决定

采用规范化标签表和资料-标签关联表，不把多个标签拼成 `resources.tags` 字符串，也不把逗号分隔文本交给前端自行解析。

### 数据模型

新增版本化迁移 `002_manual_tags.sql`，并在迁移执行器中引入 `schema_migrations` 版本记录：

```text
tags
  id              CHAR(32) PRIMARY KEY
  name            VARCHAR(40) NOT NULL
  normalized_name VARCHAR(40) CHARACTER SET utf8mb4 NOT NULL UNIQUE
  created_at      DATETIME(6) NOT NULL

resource_tags
  resource_id     CHAR(32) NOT NULL
  tag_id          CHAR(32) NOT NULL
  created_at      DATETIME(6) NOT NULL
  PRIMARY KEY (resource_id, tag_id)
  FOREIGN KEY resource_id → resources(id) ON DELETE CASCADE
  FOREIGN KEY tag_id → tags(id) ON DELETE CASCADE
```

`normalized_name` 用于唯一性和查询；展示仍保留第一次创建时的 `name`。早期 V1 提案暂不增加 `user_id`，当前多用户归属与权限边界以 [ADR 0007](0007-verified-identity-boundary.md) 及已落地迁移为准。标签不参与文件路径、文件名或 HTML 片段生成。

### 规范与边界

- 去除首尾空白；空标签拒绝；最多 24 个 Unicode 字符，数据库展示列最多 40 字符以留出规范化空间。
- 拒绝控制字符、换行和不可见分隔符；允许中文、英文、数字以及少量常用标点 `-`、`_`、`.`、`/`。
- 统一 Unicode 大小写能做的折叠（至少英文转小写）；暂不把中文同音或繁简转换当作相等。
- 每份资料最多 10 个标签；同一资料内大小写等价的重复标签只保留一个。
- 单次请求整体最多 1 KiB；超限、未知字段、重复 JSON 或非法标签全部拒绝，不做部分成功。

## API 设计

### 读取

- `GET /api/resources/:id` 在 `data` 中返回 `tags: string[]`，排序按规范化名称稳定返回。
- `GET /api/tags` 返回已有标签，支持 `q` 前缀/包含搜索和最多 50 条限制；不返回资料内容或存储信息。
- `GET /api/resources?q=&kind=&tag=&page=` 增加单个精确标签筛选。V1 先定义为“包含此标签”，多标签交集留到有实际需求时再设计。

### 替换资料标签

使用幂等的整体替换接口：

```http
PUT /api/resources/:id/tags
Content-Type: application/json

{"tags":["redis","面试准备"]}
```

- 空数组表示清空全部标签；重复提交同一数组不会产生额外语义。
- Controller 负责 JSON 体积、字段和数组结构校验；Service 负责规范化、去重、数量限制和业务错误；Repository 在一个数据库事务中确认资源、创建缺失标签、替换关联关系并返回最终标签。
- 资源不存在返回 `404`；请求不合法返回 `400`；数据库事务失败返回通用 `500`，不得泄露 SQL 或约束细节。
- 失败时旧关联关系保持不变；标签创建和关联写入不能出现半套结果。

## MVC 落点

| 层 | 计划改动 | 责任 |
| --- | --- | --- |
| Model | `Resource.Tags`、标签输入/查询结构 | 只表达跨层数据，不依赖 GORM |
| Controller | 标签路由、JSON 校验、错误映射 | 不写 SQL，不拼接标签查询 |
| Service | 规范化、去重、上限和权限边界 | 不接收 Gin 对象 |
| Repository | GORM 关联查询、事务和筛选 | 参数绑定；不决定 HTTP 状态 |
| View | 详情编辑、已有标签建议、筛选入口 | 不替代服务端校验 |

## 事务与并发

标签替换只涉及 MySQL，不涉及文件系统，因此可以用单数据库事务保证一致性。事务顺序为：校验资源存在 → 按规范化名称查找/创建标签 → 删除该资源旧关联 → 插入新关联 → 提交 → 读取稳定排序后的最终标签。

创建标签遇到唯一键竞争时，Repository 应重新查询已存在标签并继续关联，不能简单吞掉错误或生成重复数据。单管理员场景不做乐观锁；两个请求同时替换时，最后提交者覆盖前者，接口文档明确这一点。

## 前端交互

- 详情抽屉增加标签编辑区域：已有标签以可删除胶囊展示，输入框支持回车添加，保存按钮提交完整数组。
- 输入期间只做即时格式提示；最终规范化和权限以服务端为准。保存中保留焦点、阻止重复提交，失败保留用户未保存草稿并显示可读错误。
- 列表筛选增加“标签”入口；当前标签在视觉上和类型筛选一样有明确选中状态，提供清除筛选操作。
- 新增标签建议只显示服务端已有值，不能把用户输入当作可信 HTML；不使用 `innerHTML`。
- 窄屏优先保证输入、删除单个标签、保存和清除筛选都可键盘完成；`prefers-reduced-motion` 下不增加新的持续动画。

## 验收与测试

实现前先写以下失败案例：

1. 未登录、错误 Origin 和不存在资源不能修改标签。
2. 空标签、控制字符、超长标签、超过 10 个标签、未知字段和多段 JSON 返回 `400`。
3. 大小写重复标签去重；空数组能清空；重复 PUT 保持相同结果。
4. 任意一个标签创建/关联失败时，旧关联关系仍完整，不能留下孤儿标签以外的半套关联；孤儿标签清理策略另记为后续维护任务。
5. 列表按标签筛选只返回包含目标标签的资料，分页结果稳定。
6. MySQL 集成测试覆盖迁移、唯一约束、事务回滚和并发唯一键竞争的处理。
7. Vue 类型检查、构建、键盘操作、窄屏、空标签和错误恢复通过；至少完成一次真实浏览器登录后的标签编辑与筛选验证。

## 不做的事情

- 本轮不做自动分类、AI 标签、层级标签、标签颜色、标签统计、跨账号共享协作和 Redis 缓存。
- 不把标签接口设计成消息任务；标签是同步元数据写入，只有明确出现耗时处理时才进入 V2 Worker。

## 回滚

实现阶段若迁移或 UI 验证失败，回滚应用代码和 `002` 迁移；不删除已有 `001` 数据。正式迁移前先备份数据库，并在变更记录中记录回滚演练结果。
