# ADR 0011：批量删除的事务与文件清理

- 日期：2026-09-30
- 状态：已采纳

## 背景与决定

站内文件、派生正文和站外卡片不能以多个独立请求假装整批原子删除；数据库与文件系统也不能参与同一事务。服务端先用会话范围锁定并校验完整批次，事务内软删除站内资料、移除标签和处理任务/派生索引（外键级联 outbox）、删除外部卡片，并把每个原件及派生文件的服务端存储键写进持久 `pending_file_cleanup` 表。任一步失败回滚整批，不访问任何文件。完成事务后才按受控 ID 清理文件；成功后移除对应账本条目。API 启动后及每分钟有界重试剩余条目，跨实例重复清理按文件不存在即成功处理。

API 必须区分 `deleted` 与 `cleanup_pending`：后者表示数据库删除已经成功，客户端不得因清理失败而重发不可逆批次。前端要求输入数量确认并直说不可撤销。外部卡片仅删除本站索引，绝不访问或删除外部原件。

## 代价与后续

当前单项删除是先软删除、清理原件，未统一清理既有派生产物；历史数据和备份的留存须单独审计。文件系统长期不可用会让账本积压，需告警/运维处理；这不是强制即时物理抹除，更不覆盖已经生成的备份。已整理资料仍缺批量选择入口，浏览器手动验收尚未完成。
