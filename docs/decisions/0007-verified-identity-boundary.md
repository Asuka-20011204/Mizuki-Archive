# ADR 0007：多用户验证码身份与资料隔离边界

- 日期：2026-09-29
- 状态：**产品边界与邮箱 HTTP 闭环已确认，真实环境验收进行中**

## 背景

项目现在只有从环境注入的单管理员密码；MySQL `sessions` 无账号 ID，`resources`、`tags`、`processing_jobs` 和派生产物也没有所有者。用户希望加入邮箱或手机号验证码注册登录，但若仅增加新账号或新会话，所有新登录者会直接看到原有私有资料。

## 已确认的产品边界

允许不同邮箱注册，每人只能管理自己的资料；“个人数字信息管理”描述的是每个用户的使用场景，不是系统只能有一个用户。先迁移原管理员账户及资源归属，再开放注册和验证码登录。需要给资料、标签/关联、任务和派生产物、最近访问缓存与会话建立一致的所有者边界，所有读写以服务端身份限定，而不能依赖前端传入用户 ID。

迁移需要可重复、可回滚的备份方案，兼容旧会话策略必须明确，越权请求包括资源详情、下载、预览、搜索、处理任务和派生产物。

## 共同的安全约束

- 首先实现邮箱 SMTP；手机号验证码需要独立短信服务商与成本/合规配置，不在仓库伪造短信发送。
- 邮件连接必须 TLS 且校验证书；发件人、收件人与验证码严格校验。邮件服务不可用时不返回“已发送成功”的假状态。
- 验证码使用加密安全随机数，摘要存储，短时有效，按地址/IP 限流、限尝试和重发，成功后事务性一次消费；返回信息避免枚举账号，记录只含最小必要元数据。
- 测试至少包括重复消费、并发竞态、过期、错误次数、无 TLS、发送失败、跨账号资料读取/任务访问以及浏览器完整注册/登录/退出流程。
