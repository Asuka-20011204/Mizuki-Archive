# 安全与隐私基线

个人资料库的首要资产是**原始文件、派生文本、访问凭据和元数据**。默认私有；不能因为产品名称包含“个人”或本地演示只有一个账号就跳过鉴权。正式设计必须按多个独立用户的越权风险执行。

## 访问与配置

- 每个资源、任务、预览、下载、删除接口都鉴权；当前多用户查询必须通过服务端会话注入的 `user_id` 过滤，不能信任请求体或 URL 中的所有者字段。不要暴露文件目录的静态 HTTP 映射。
- 批量标签在当前会话内限制请求体 8 KiB 并消费至 EOF（拒绝尾随第二个 JSON 和超大空白）、批次 1–50 项、每用户本地限流及可选共享限流；对全部条目先校验归属与软删除，再在同一事务中写入。跨用户混合批次整体拒绝且不泄漏哪一项属于他人；反向操作目前没有版本化冲突保护，前端须提示并发覆盖风险。Redis 不可用时退回单实例本地限流，不能称为跨实例额度。
- 批量收藏同样要求完整 8 KiB JSON、显式 `favorite` 布尔值、1–50 个不同条目及用户范围限流；仓储先锁定全部本人条目，软删除文件或混入他人 ID 整批拒绝，不返回他人收藏状态。反向操作是新的目标状态写入，不能当作无冲突回滚；共享限流不可用时仅剩逐实例限制。
- 批量删除限制 8 KiB 完整 JSON、至多 50 项、明确 `confirm: "DELETE"`、当前会话和本地/可选共享限流；前端另要求用户输入删除数量。仓储先锁定并校验所有归属，越权或缺失整批回滚。事务清除站内文件的派生正文/任务元数据、外部卡片，以及原件/派生文件待清理键；提交后只按受控 32 位 ID 删除本地文件。失败留在 `pending_file_cleanup` 账本，API 启动后及每分钟有界重试。`cleanup_pending` 不是事务失败，**不能让客户端重试整批删除**。日志只记录失败数量，不输出文件名、路径和正文。备份、旧版单项删除残留及暂时无法访问的存储节点仍须另外纳入数据保留与清理审计。
- 首版身份机制实现前再定稿；若用 Cookie 会话，要考虑 HttpOnly、Secure、SameSite 与 CSRF；若用 JWT，避免浏览器持久化明文 token，并设计过期、撤销与轮换。登录接口限流，密码使用成熟的口令哈希方案，不自造加密。
- 密钥、数据库密码、会话密钥只从运行环境或密钥管理注入；`.env.example` 只放变量名称和占位符。日志、错误响应、仓库、截图与 CI 输出都不得泄露凭据。

## 数据库权限边界

- 本地 `go run ./cmd/server` 默认允许自动迁移，目的是保持开发环境开箱即用；生产环境必须设置 `APP_AUTO_MIGRATE=false`，不能把开发默认值当作生产权限策略。
- 生产部署由 `db-access-bootstrap` 创建独立迁移账号和运行账号；`cmd/migrate` 只在一次性容器中使用 `MIGRATION_DSN` 执行 DDL、管理员初始化和旧数据归属回填。
- API/Worker 只使用运行 DSN，当前权限为 `SELECT`、`INSERT`、`UPDATE`、`DELETE`，不应拥有 `CREATE`、`ALTER`、`DROP` 或 `GRANT OPTION`。数据库用户权限变化必须通过编排和变更记录审查，不能手工扩大权限后继续部署。
- 迁移账号密码、运行账号密码和 MySQL root 密码必须不同；账号初始化日志不得输出密码、完整 DSN 或管理员哈希。迁移容器退出后不应作为常驻服务运行。
- 迁移命令在执行 DDL 前验证管理员哈希格式；已有兼容管理员再次迁移时，仅在配置哈希发生变化时原子更新密码哈希，错误配置不会覆盖有效密码。

## 入口代理与限流

- `web/nginx.conf` 在认证入口和 `/api/` 入口按 `$binary_remote_addr` 做第一层限流；它是抗突发和降低昂贵请求压力的边界，不替代 API 的验证码一次性消费、Redis 共享限流和权限校验。
- API 默认不读取 `X-Forwarded-For` 或 `X-Real-IP`，防止直连客户端伪造地址。只有 API 不映射宿主端口、Nginx 明确覆盖 `X-Real-IP` 且 `APP_TRUST_PROXY_HEADERS=true` 时才读取该值。
- 若部署在多层代理后，必须把可信代理范围、地址覆盖行为和入口限流策略一起审计；不能仅设置环境变量就宣称真实 IP 和限流已经可靠。

## 邮箱验证码边界

邮箱验证码已接入多用户注册/登录的代码路径；`internal/notification/smtp.go` 只实现强制 STARTTLS/隐式 TLS 的 SMTP 发送。验证码不可明文持久化或写日志，需限制有效期、尝试次数和重发频率、原子消费并避免账号枚举。SMTP 凭据仅通过私有运行环境注入，拒绝 TLS 降级；未配置真实邮箱提供方时不暴露验证码路由。

大陆手机号只接受 11 位 ASCII 数字（首位 1、第二位 3–9）或 `+86` 前缀，统一保存为 `+86` 加 11 位；格式检查不代替真实号码验证。手机号唯一索引与邮箱独立，不能用输入号码认领旧邮箱账号。挑战与邮箱隔离，使用 HMAC 摘要、10 分钟有效、1 分钟冷却、5 次错误限制、行锁一次性消费；短信请求按 IP 和号码限额，Redis 的号码键用服务端密钥派生而非普通哈希，共享限流器存在但故障时拒绝费用型请求。**当前没有短信适配器和凭据：服务器不注入 `PhoneAuth`，能力为 `false`，路由不注册。**供应商接入前还须核查官方接口、签名模板、预算、短信轰炸、日志脱敏与个人信息保留期。

手机号入口仅面向中国大陆手机号，不开放港澳台及其他国家/地区号码；前端格式提示不能代替服务端校验或真实性验证。归档与恢复仅在私有会话中执行，批次在事务内先核验全部条目归属，归档列表按会话用户隔离；归档不是删除，下载与详情仍按当前账号授权，前端不得缓存或展示其他账号的归档结果。

重复提醒查询必须由会话用户限定 `user_id`，排除当前项；文件还要过滤软删除记录。外部地址规范化和摘要仅在服务端做纯文本操作，不探测站点、解析内网主机或下载内容；本地路径及不合规 URL 不查重。响应只包含同账号已有项的 ID/名称，不返回内部存储键；前端以文本渲染提示。迁移旧卡片只增加索引摘要，不能更改原地址或自动删除任何资料。

统一搜索必须按服务端会话用户过滤文件与卡片，不能让关键词猜测其他账号的名称、正文或标签；文件已软删除时，即使派生正文仍存库也不得命中。输入长度、控制字符和分页在 Service 与 Controller 校验，SQL 使用绑定参数，外部卡片 `LIKE` 特殊字符转义；只返回授权元数据，不把派生正文或数据库错误返给浏览器。搜索按账号每分钟 30 次共享/本地双层限流，单次查询 5 秒超时；模糊搜索跨数据规模仍可能消耗较多数据库资源，公网部署须结合入口限流、连接池与性能监控复测，不将有限页数误当作扫描成本上限。

保存的检索视图包含可能敏感的关键词与标签，应按私人资料保护数据库和备份；列表、创建、删除都使用会话中的 `user_id`，视图归属不能由请求指定。保存只存条件，不保存匹配结果或正文；打开视图后仍走实时搜索校验、账号归属与限流。账号内重名由唯一索引拦截，账号行锁把最多 30 个视图的限制跨 API 实例保持一致；生产发布先执行 `014` 迁移，再启动依赖新表的 API。

## 多用户归属

- `sessions.user_id` 和 `resources.user_id` 是服务端权限边界；任务和派生产物通过资源关系继承归属，HTTP 查询必须带资源归属条件，Worker 才允许使用系统级全局领取路径。
- Redis 最近访问、任务缓存和标签缓存都使用用户命名空间；缓存失效不能替代 MySQL 权限校验。
- 启动迁移先创建/回填兼容管理员用户，再把旧资源和会话归属到该用户；邮箱占位地址 `@local.invalid` 不视为已验证邮箱。

## 上传与处理

外部资源卡片的位置字段只按长度和控制字符校验后保存为文本；服务端不抓取、不下载、不自动登录第三方站点，也不根据它读本机路径，防止 SSRF 与路径穿越。卡片与上传文件使用不同表；按会话用户 ID 过滤所有读写，跨用户 ID 返回与不存在一致的 404。前端通过 Vue 文本插值显示位置，不注入 HTML；不自动发起站外请求。现阶段不保证用户填写的链接可用，状态仅由本人手动维护。

粘贴预填仅解析当前浏览器的明文输入，不调用浏览器权限 API 读取剪贴板，也不对第三方链接发请求；只接受无 URL 内嵌凭据的 HTTP(S) 地址。提取码是用户自愿保存在私有卡片中的信息，禁止在公共日志或公开页面展示；成功保存后清除原粘贴片段在表单中的副本。用户仍需自己判断分享链接是否可信，系统不承诺外部内容真实性。

收件箱按会话用户 ID 查两张表，写入同时限定用户与资料 ID；没有会话的请求拒绝，跨用户写入返回 404。整理状态不能通过外部卡片普通编辑请求伪造，必须走限长且同源校验的专用接口。迁移前备份库，因旧资料首次升级会显示待整理；标记“已整理”不改变私有归属、文件内容或外部地址。

批量整理沿用同源会话检查，请求体上限 8 KiB、条目上限 50，拒绝重复/非法 ID；先锁定并检查两表所有行的归属和文件未删除状态，再在同一个事务中更新，任一失败则整批回滚。前端勾选、确认和撤销不是权限边界；撤销仍需服务端归属校验。并发修改同一资料时撤销可能覆盖同用户另一会话的新整理状态，当前只在一次操作后显示单次撤销；未来若要强一致撤销须引入操作版本或审计记录。

- 服务端限制请求总体大小、单文件大小、类型与扩展名；校验文件内容特征，不能仅信任 `Content-Type` 或后缀。拒绝不支持的格式，设定用户空间配额和提交频率限制。
- 存储使用生成的内部键与受控根目录，不用原始文件名拼接路径；规范化并验证路径边界，阻止 `..`、绝对路径、符号链接绕过与同名覆盖。临时文件使用隔离目录和清理策略。
- 原件与派生文件不直接作为可执行内容提供；按需下载时使用安全的 Content-Disposition/类型头。渲染 Markdown/提取文本必须安全转义或经过可信净化，限制 HTML/脚本，明确内容安全策略。
- 文件处理器对畸形 PDF、图像和压缩炸弹设置大小、页数/像素、CPU/内存/时间上限；Worker 使用最低权限、隔离目录、不允许未经授权的网络访问，不依赖未知来源的可执行附件。
- 不在 Redis 或 MQ 中存放原文件或完整提取文本；消息只引用任务 ID。缓存、日志、错误与备份均按敏感数据处理，明确保留期限与清理路径。

## 数据一致性与恢复

- SQL 使用参数化查询；事务只能保证数据库内部一致性，文件系统和 MQ 的失败需补偿、巡检或 outbox。下载和删除均记录审计需要的最小事件，不记录文件正文。
- 备份包括数据库**和文件目录**，加密、限制访问并定期演练恢复；删除覆盖原件、派生物、索引、缓存和可控备份保留策略。避免在共享演示环境上传真实隐私资料。
- 依赖与容器镜像在引入后做版本锁定、漏洞检查；出现凭据泄露先撤销/轮换，再清理历史与排查访问日志。不要因为 `.gitignore` 命中就认为安全。

## 合并前检查

检查身份绕过、越权读取、路径穿越、任意文件上传、注入/XSS、敏感错误回显、重复任务副作用、无限重试与资源耗尽；针对每一项保留可复现测试。

## V2 处理任务安全

- 任务请求只提交白名单类型和资料 ID，不接受文件正文、目标路径或处理器参数；Worker 从受控存储键读取原件。
- 任务创建记录原件 SHA-256；Worker 领取后再次比对资料哈希和存储键，资料被删除或替换时不生成产物。
- 派生产物写入 `APP_DATA_DIR/derived`，使用随机存储键、临时文件和原子移动；数据库完成提交失败时删除已移动文件。
- PDF/TXT/Markdown 只生成纯文本，前端使用文本节点显示；Markdown 不转 HTML，原件下载强制附件。例外：认证后的 PDF 预览单独以可信 `application/pdf` MIME 内联提供给浏览器查看器，不允许 HTML/脚本作为可内联类型；未经认证的预览仍返回 401。
- 任务有最大尝试次数、输出大小上限和租约；失败摘要不保存本地路径、堆栈、原文或凭据。`content_text` 仅用于同一私有资料库的关键词检索，不对外直接返回。
- 图片缩略图在 Worker 中使用独立 `generate_thumbnail` 任务；解码前限制单边 12,000 像素和 4,000 万总像素，输出最大 640×640 PNG，原件只读，派生产物使用随机键保存。异常图片、方向信息和孤儿派生产物仍属于 V2 后续专项回归，不影响 V1 资料管理退出条件。

## V3/V4 外部组件边界

- RabbitMQ 仅传版本和任务 ID；非法 JSON、未知字段、负数或超限重试头进入隔离队列，不执行处理器。发布确认和后置 ACK 配合事务 Outbox，但允许重复消息；数据库租约和最大次数决定执行状态。
- Redis 不存原件、正文、文件路径和 Cookie；私有资料列表、详情与下载仍回查 MySQL。最近访问最多 20 个 ID、90 天到期，删除时清除关联成员；Redis AOF 和备份也按可能含过期 ID 的敏感数据处理。
- Redis 共享登录限流仅在可用时生效；故障时回退单进程失败尝试限制。生产部署仍需入口层限流、故障告警以及 Redis/Broker 网络隔离。
- 可选容器密码为空即启动失败；本地 `.env` 不入库。Redis 运行配置写入受控临时文件，不把密码放在服务器命令参数中。
- V14 的 `compose.secrets.yaml` 只把秘密文件以只读方式挂载到需要它的服务；程序支持 `NAME_FILE`，当非空 `NAME` 与 `NAME_FILE` 同时存在时拒绝启动，避免运维误用旧凭据。Secrets 文件必须位于仓库外、限制文件权限，并在轮换后重建相关容器。
- `compose.tls.yaml` 只读取外部 `TLS_CERT_FILE` 和 `TLS_KEY_FILE`，证书私钥不进入 Git、镜像或普通日志。TLS 配置使用 TLS 1.2/1.3、关闭 session ticket，并启用 HSTS；本地 HTTP 编排不因该覆盖而改变。
- `scripts/scan-images.ps1` 是发布前门禁，使用 Trivy 检查 Compose 解析出的镜像并对未修复的 HIGH/CRITICAL 漏洞失败；未安装 Trivy 或未执行扫描时不得声称镜像已通过漏洞验收。
